# 두 프로젝트와 추가 프로젝트의 팀 구분

- 기존 프로젝트: 기존 11명, 기존 채널·게시물·자료 유지.
- 추가 프로젝트: 1팀 6명(`로봇-1a`), 2팀 5명(`로봇-1b`).
- 웹의 프로젝트 선택지는 정확히 두 개이며 추가 프로젝트에서 팀을 선택한다.
  프로젝트 전체 또는 두 팀을 합쳐 검색하는 선택지는 제공하지 않는다.

## 수집과 저장

`bot/projects.py`가 공통 범위 정의다. 기존 category 값은 기존 프로젝트로
유지하고, 신규 자료에는 `robot_1a` / `robot_1b` category를 저장한다. 파일 DB와
대화 DB 모두 같은 태그를 사용한다. 스키마 변경·기존 원본 이동·재업로드는 없다.

사용자가 제공한 1a 채널 ID는 고정한다. 1b는 지정 서버에서 `로봇-1b`와
일치하는 텍스트 채널이 하나일 때만 찾는다(이름 끝 이모지 허용). 다른 서버,
유사한 이름, 중복된 이름을 추측해서 연결하지 않는다. 이후 수집된 자료에
저장된 채널 ID로 연결을 유지하므로 자료 수집 후 이름을 바꿔도 재시작 시
복원한다. 새 채널 생성 이벤트와 봇 재연결에서도 수집기·이력 커서를 갱신한다.
채널의 공개 스레드도 부모 팀의 범위를 따른다. 기존 비공개 스레드의 권한
검사는 그대로 유지한다.

원본과 메타데이터는 기존 `storage/<category>` 규칙을 따라 팀별 폴더에
저장한다. Drive는 기존 폴더를 유지하고 `추가 프로젝트 - 1팀`,
`추가 프로젝트 - 2팀` 폴더를 별도로 만든다.

## 조회 경계

웹 API·원본 URL의 기본 범위는 기존 프로젝트다. 추가 프로젝트는
`project=additional&team=1a` 또는 `team=1b`를 사용한다. 잘못된 프로젝트나
팀 누락은 400이며, 다른 범위의 파일 ID·대화 ID 조회는 404다. 상세·다운로드·
텍스트/PDF/이미지/HTML/DOCX 미리보기·파일 AI에도 동일한 경계를 적용한다.

목록·검색·건수·채널/확장자 선택·처리 상태·중복/버전 관계·대화의 첨부·
AI 검색과 주변 대화·주간 요약을 모두 범위 안에서 조회한다. 주간 저장 파일은
`weekly-summary-main.json`, `weekly-summary-1a.json`, `weekly-summary-1b.json`으로
분리한다. 기존 `weekly-summary.json`은 범위가 없으므로 재사용하지 않는다.
AI 캐시는 자료 ID·원문·출처를 포함하는 기존 키와 공유 사용 한도를 유지한다.

범위 변경 시 열린 자료·검색 조건·AI 답변·주간 요약을 초기화한다. 이전
범위에서 늦게 도착한 응답은 표시하지 않는다. 공유 주소에도 프로젝트·팀을
포함한다. 기존 프로젝트의 기존 공유 주소는 계속 사용할 수 있다.

## Discord 명령

11개 명령을 유지한다. 도움말을 제외한 명령에 `자료범위` 선택지를 추가한다.
선택지는 기존 프로젝트 / 추가 프로젝트 1팀 / 추가 프로젝트 2팀이다.
생략하면 명령을 실행한 채널의 범위를 사용한다. 파일 자동완성·통합 검색·
상태·요약·질문에도 적용하며, 현재 Discord 열람 권한 검사는 함께 적용한다.
범위 구분은 웹 사용자 인증/접근 제한을 새로 만드는 기능이 아니다. 기존
웹 공유 방식은 유지한다.

## 배포

Python 3.11과 기존 고정 의존성을 사용한다. 추가 패키지·DB 마이그레이션·
설정 파일 교체가 없으므로 [PHONE.md](../deploy/raspberry-pi/PHONE.md)의 코드
배포 절차를 따른다. 봇과 웹을 같은 커밋으로 함께 배포해야 범위가 일치한다.
배포 후 새 채널에서 봇의 채널 보기·메시지 기록 보기 권한과 실제 수집을
확인하고, 웹에서 프로젝트·팀을 바꿔 목록과 AI 참고 범위를 확인한다.
